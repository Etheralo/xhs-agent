# Paper→Post 论文内容控制台使用说明书

> 适用项目：AI Safety 论文内容 Agent  
> 适用方式：本机编辑控制台＋命令行  
> 默认地址：<http://127.0.0.1:8765>

## 1. 这个系统能做什么

Paper→Post 用于把候选论文整理成可审核、可追溯、可发布的中文内容包。
它可以：

- 搜索 arXiv 论文，并将单篇论文加入本地选题库；
- 扫描近期 AI Safety 论文，或运行 3 篇离线构造样例；
- 提醒论文会议或发表证据的核验状态，也允许稍后补充；
- 直接导出真实论文 PDF 的前 6 页作为小红书配图，并生成小红书文案和微信公众号长文；
- 查看事实底稿、页码引用、校验结果和操作记录；
- 通过 6 项人工审核后生成 ZIP 发布包；
- 自动把 6 张配图、标题和正文填入小红书发布页，由编辑核对后手工点击发布；
- 向用户自有的发布连接器发送发布包，或由编辑手工发布。

系统不会把 arXiv 收录当成顶会录用证明，也不会跳过人工审核。

## 2. 首次安装

### 2.1 环境要求

- Python 3.11 或更高版本；
- `uv` Python 包管理工具；
- 真实论文搜索和 PDF 下载需要可访问互联网；
- 建议使用 Chrome、Edge 或 Safari 的较新版本。

### 2.2 安装依赖

在项目根目录执行：

```bash
uv sync --dev
cp .env.example .env
```

`.env` 只保存在本机，不要将真实密钥提交到版本库。

### 2.3 配置内容生成模型

编辑 `.env`：

```dotenv
OPENAI_API_KEY=你的密钥
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=your-model-name
LLM_STREAM=true
LLM_JSON_MODE=true
LLM_DISABLE_THINKING=true
LLM_READ_TIMEOUT_SECONDS=600
LLM_MAX_INPUT_CHARS=55000
LLM_MAX_COMPLETION_TOKENS=4096
```

这里的 `OPENAI_*` 表示接口协议，不限定模型厂商。只要服务支持 OpenAI-compatible
`/chat/completions` 接口，就可以把 `OPENAI_BASE_URL` 和 `OPENAI_MODEL` 改成对应值。
默认使用流式响应和 JSON mode；对 Kimi 模型会关闭思考模式。模型读取超时、论文输入
字符上限和模型输出上限可通过上述 `LLM_*` 变量调整。程序不会对超时请求自动重试，
避免原请求仍在服务端执行时产生重复调用和重复计费。

没有填写 `OPENAI_API_KEY` 时，系统仍能启动和运行构造样例，但真实论文只能使用
更保守的规则模式，生成效果会受限。

OpenAlex 是可选的辅助来源：

```dotenv
OPENALEX_API_KEY=你的密钥
```

OpenAlex 匹配结果只用于辅助判断，不能单独作为会议录用证据。

## 4. 页面区域说明

| 区域 | 用途 |
| --- | --- |
| 内容工作台 | 唯一提供论文搜索；负责发现、导入和生成内容 |
| 审核队列 | 以更宽的内容区查看文案、配图与证据，只显示等待审核内容 |
| 发布中心 | 以内容和渠道状态为主，查看已批准或已发布内容 |
| 运行记录 | 查看最近一次扫描或生成任务的状态 |
| 顶部状态栏 | 始终位于页面上方，显示已入库、已生成内容、已通过审核和已发布数量 |
| 候选论文 | 按标题、arXiv ID 或状态筛选本地论文库 |
| 论文详情 | 生成内容、查看产物、补充证据、审核和发布 |

## 5. 真实论文的标准工作流

### 步骤 1：搜索并加入选题

1. 进入“内容工作台”，在搜索框输入至少 2 个字符，例如 `prompt injection`。
2. 点击“搜索 arXiv”或按回车。
3. 在搜索结果中阅读标题、作者、arXiv ID 和日期。
4. 点击“加入选题”。如果显示“已在库中”，则不会重复导入。

搜索只代表在 arXiv 中发现了该预印本，不代表论文已被任何会议录用。

### 步骤 2：生成或完成初筛

1. 在本地候选列表中选中论文。
2. 点击论文详情右上角的生成按钮。
3. 系统在后台完成主题筛选、来源提醒、PDF 抽取、事实抽取和内容生成；模型流式返回时，页面会持续展示正文生成过程。

真实论文没有可信会议证据时仍可继续生成。页面会显示提醒，但不会把来源写成已核验会议论文。

### 步骤 3：补充会议官方证据

1. 打开该论文的“来源证据”标签。
2. 在“会议名称”中填写正式名称。
3. 在“官方证据网址”中填写会议官网的 accepted papers 或正式 proceedings 页面。
4. 保存即可；来源核验不是生成或审核的强制条件。

建议优先使用会议官网、USENIX、IEEE、ACM 或 Springer 等正式出版页面。请勿仅填写
arXiv 链接、个人主页或搜索结果页。

### 步骤 4：检查生成结果

内容生成完成后，论文状态变为“已生成内容”。依次检查：

1. **论文概览**：标题、摘要、作者、评分和发表信息。
2. **小红书**：论文 PDF 前 6 页配图，以及独立标题和完整正文。标题采用“会议简写：核心总结”格式，核心总结最多 15 字；正文必须包含论文题目、会议来源、研究摘要、研究背景、核心创新和实验结果六部分，并保持在 1000 字内。
3. **公众号**：长文的结构、描述准确性和来源标注。
4. **来源证据**：会议证据、事实底稿、核心主张、PDF 页码和校验结果。

在论文处于“已生成内容、等待审核”状态时，小红书标题、正文和公众号全文都可以直接在
网页文本框中修改。点击“保存文本修改”后，页面产物、公众号 HTML 和后续发布包会同步
使用新版本。通过审核后文本转为只读，避免审核内容与实际发布内容不一致。也可使用
“复制小红书标题与正文”或各标签中的复制按钮。

### 步骤 5：人工审核

1. 点击“开始内容审核”。
2. 逐项完成下列 6 项检查：
   1. 论文确实值得发布；
   2. 问题和方法没有讲反；
   3. 核心数字能在标注 PDF 页码找到；
   4. 通俗例子不误导；
   5. 编辑推演没有写成作者结论；
   6. 6 张发布配图清晰可读（真实论文为 PDF 前六页）。
3. 选择需要准备的发布渠道。
4. 输入审核人姓名。
5. 点击“批准并生成发布包”；启用小红书浏览器模式时点击“批准并填充到小红书”。

任意检查项未勾选、审核人为空，或未选择渠道时，系统不会批准内容。

### 步骤 6：发布

#### 方式 A：手工发布

未配置发布连接器时：

1. 审核后点击“下载发布包”。
2. 解压 ZIP，获取论文前六页配图、小红书文案、公众号长文、事实底稿和审核清单。
3. 由编辑登录对应平台完成发布。
4. 回到发布中心，点击“确认已经发布”。

“确认已经发布”只记录业务状态，不会再向平台发送内容。

#### 方式 B：小红书专用浏览器自动填充、人工发布

在 `.env` 中配置：

```dotenv
XHS_PUBLISH_MODE=browser
XHS_BROWSER_CHANNEL=chrome
XHS_BROWSER_HEADLESS=false
XHS_PUBLISH_TIMEOUT_SECONDS=180
```

首次使用或登录失效后运行：

```bash
uv sync --dev
uv run playwright install chrome
uv run xhs-agent xhs-login
```

在打开的专用 Chrome 中完成短信登录，进入发布页面后回到终端按 Enter。审核通过后，
后台任务会上传 6 张论文配图并填写标题和完整正文，随后停止自动化操作，保留已填写的
Chrome 页面。程序不会点击“发布”。请人工核对图片、标题和正文，在小红书页面点击发布；
确认平台发布完成后，回到控制台点击“我已手动发布”。收到这项用户反馈后，系统才把内容
记为“已发布”。登录失效时任务会提示重新登录。

#### 方式 C：用户自有发布连接器

在 `.env` 中配置：

```dotenv
XHS_PUBLISH_MODE=webhook
XHS_PUBLISH_WEBHOOK_URL=https://your-publisher.example/xhs
WECHAT_PUBLISH_WEBHOOK_URL=https://your-publisher.example/wechat
PUBLISH_WEBHOOK_TOKEN=your-private-token
```

修改 `.env` 后重启控制台。审核弹窗中显示“连接器已就绪”时，批准操作会将发布包发送至
相应连接器。

连接器必须接收 `multipart/form-data`：

- `metadata`：JSON 元数据；
- `package`：通过人工审核、包含 SHA-256 清单的 ZIP 文件；
- 如已配置 token，请求头中包含 `Authorization: Bearer <token>`。

连接器应返回 JSON，`status` 支持：

| 状态 | 含义 |
| --- | --- |
| `delivered` | 发布包已送达连接器 |
| `submitted` | 已提交至平台，正在处理 |
| `published` | 连接器确认已发布 |

如果所选渠道全部返回 `published`，论文整体状态会自动更新为“已发布”。
连接器发送失败时，系统会记录失败，不会误标为已发布；仍可下载 ZIP 后手工处理。

## 6. 状态说明

| 页面状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 已入库 | 论文已进入本地库，尚未生成完整内容 | 点击“生成内容” |
| 已生成内容 | 正文、配图和自动检查已完成 | 执行 6 项人工审核 |
| 已通过审核 | 人工审核完成，发布包可用 | 填充发布页并由用户手动发布 |
| 已发布 | 平台发布已确认 | 归档，必要时重新下载发布包 |

状态依次推进。不符合选题范围的论文直接删除，不保留拒绝状态或拒绝记录。

## 7. 全量扫描与批量生成

在控制台首页点击“扫描并生成”，系统会根据 `config/settings.yaml` 中的配置：

- 扫描默认为最近 7 天；
- 最多获取 50 个候选；
- 默认选择 1 篇论文生成；
- 只处理配置中的 arXiv 分类和 AI Safety 主题；
- 未核验来源仅显示提醒，不阻塞内容生成。

运行期间页面会显示工作状态。可在“运行记录”中查看最近结果。后台同时只执行
一个生成任务，其余任务会排队。

## 8. 命令行使用

控制台和命令行共用同一个 SQLite 数据库和产物目录。

```bash
# 初始化数据库
uv run xhs-agent init-db

# 运行真实扫描
uv run xhs-agent run

# 运行 3 篇构造样例
uv run xhs-agent run --demo --select-count 3

# 列出全部论文或只看待审论文
uv run xhs-agent list
uv run xhs-agent list --status ready_for_review

# 查看审核队列和单篇论文
uv run xhs-agent review
uv run xhs-agent show 1

# 审核、导出、记录已发布
uv run xhs-agent approve demo.00001 --reviewer "编辑姓名"
uv run xhs-agent export demo.00001
uv run xhs-agent mark-published demo.00001
```

`show`、`approve`、`export` 和 `mark-published` 可使用数据库 ID，也可使用 arXiv ID。

## 9. 数据与文件位置

默认情况下：

- SQLite 数据库和下载数据位于 `data/`；
- 每篇论文的生成结果位于 `output/<日期>/<论文>/`；
- 通过审核后会生成 `FINAL-APPROVED.json`；
- 导出后会在论文产物目录中生成 `*-approved.zip`。

单篇生成目录通常包含：

- `xhs-title.txt`：独立的小红书标题；
- `xhs-caption.md`：不重复标题的小红书正文；
- `wechat.md` / `wechat.html`：公众号正文；

```text
source.json
facts.json
validation.json
xhs-slides.json
xhs-caption.md
publication-images.json
xhs-01.png ... xhs-06.png
wechat.md
wechat.html
```

如需改用其他目录，可在 `.env` 中设置：

```dotenv
XHS_AGENT_DATA_DIR=/absolute/path/to/data
XHS_AGENT_OUTPUT_DIR=/absolute/path/to/output
```

修改目录后需重启控制台。

## 10. 常见问题

### 页面打不开

- 确认运行 `uv run xhs-agent serve` 的终端没有被关闭；
- 确认访问的是 `http://127.0.0.1:8765`，而不是 HTTPS；
- 如端口被占用，使用 `--port 9000` 更换端口。

### `uv` 提示缓存目录无权限

如果出现 `Failed to initialize cache` 或默认 `~/.cache/uv` 无法写入，可指定一个可写缓存目录：

```bash
UV_CACHE_DIR=/private/tmp/xhs-agent-uv-cache uv sync --dev
UV_CACHE_DIR=/private/tmp/xhs-agent-uv-cache uv run xhs-agent serve
```

已安装好项目本地 `.venv` 时，也可直接使用 `.venv/bin/xhs-agent serve`。

### arXiv 搜索失败

- 检查本机网络是否能访问 arXiv；
- 关键词必须至少包含 2 个字符；
- 稍后重试，避免短时间内频繁查询。

### 页面提示“来源尚未核验”

这是非阻塞提醒。可以继续生成和审核；如需补充，打开“证据与记录”，填写正式会议名称
和 HTTP(S) 官方证据网址后保存。

### 没有生成发布包

只有“已生成内容”状态的论文才能审核。必须勾选全部 6 项检查、选择至少一个渠道并填写
审核人姓名。

### 点击“填充到发布页面”后没有自动发布

这是预期行为。浏览器模式只上传图片并填写标题、正文，永远不会点击小红书的发布按钮。
请在保留的 Chrome 页面核对并手动发布，再回控制台点击“我已手动发布”。如果连内容也
没有填入，请检查渠道是否显示“专用浏览器”，并查看运行记录或终端错误。配置修改后必须
重启服务。

### 生成内容不完整或过于保守

先检查 `.env` 中的 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL`。页面左下角的
“配置状态”可用于确认模型和数据源是否已配置。

### 如何查看错误细节

- 先查看页面右上角提示和“运行记录”；
- 查看启动控制台的终端输出；
- 查看论文“来源证据”中的校验结果和操作记录。

## 11. 安全与运营建议

- 控制台默认只监听 `127.0.0.1`，且没有用户登录功能；不要直接暴露到公网。
- 不要在浏览器、前端代码、论文文案或发布包中填写 API 密钥。
- 每篇真实内容都应对照论文 PDF 和官方发表证据做最终审核。
- 自动校验通过不等于学术事实已由人工确认。
- 小红书普通账号没有连接器时，使用 ZIP 发布包手工发布。
- 建议定期备份 `data/` 和已批准的 `output/` 目录。

## 12. 验收清单

首次部署后，建议按以下顺序验收：

- [ ] 控制台可以在本机打开；
- [ ] “运行示例”能生成 3 篇待审样例；
- [ ] 任选一篇真实论文可查看 PDF 前 6 页配图和双渠道文案；
- [ ] 事实底稿、校验结果和操作记录可查看；
- [ ] 审核弹窗会拒绝不完整检查；
- [ ] 完成审核后可下载 ZIP 发布包；
- [ ] 浏览器模式可填入 6 张图片、标题和正文，且不会自动点击发布；
- [ ] 手工确认后，内容会出现在“已发布”列表；
- [ ] 如配置了 webhook，连接器能正确接收 metadata 和 ZIP。
